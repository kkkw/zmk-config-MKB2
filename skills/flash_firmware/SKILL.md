# MKB2 ファームウェア書き込み

## 安全条件

1. 利用者に、書き込み対象の左右とモジュールを確認する。
2. 対象UF2のファイル名を確認する。左エンコーダーは `MKB_L_MODULE_ENC.uf2`、右トラックボールv4は `MKB_R_MODULE_TBv4.uf2` を使う。
3. 利用者に対象側だけをUSB接続してもらい、リセットボタンを2回押してブートローダーモードへ入れてもらう。
4. `/Volumes` 以下に `INFO_UF2.TXT` を持つドライブが1つだけ現れたことを確認する。
5. 対象、UF2、検出したドライブを利用者へ提示し、明示的な確認を得るまでコピーしない。

## 利用者が行う物理操作

通常のファームウェア更新では、次の手順を片側ずつ行う。

1. 左右両方の電源スイッチを切り、USBケーブルを外す。
2. データ通信対応のUSBケーブルを、今回書き込む側だけに接続する。USB給電されるため、書き込み中は電源スイッチを切ったままにする。
3. 対象側のXIAO nRF52840に接続されたリセットボタンを、約0.5秒以内に素早く2回押す。
4. macOSのFinderへUF2ドライブが現れるまで数秒待つ。ドライブ名だけで判定せず、`INFO_UF2.TXT` があることを確認する。
5. エージェントへ対象側とready状態を伝える。利用者自身ではUF2をコピーせず、dry-runの表示を待つ。
6. エージェントがUF2、artifact名、ドライブ情報を提示した後、書き込み実行を明示的に承認する。
7. コピー中はUSBを抜かない。完了するとUF2ドライブが自動的に消え、コントローラーが再起動する。
8. もう片側も更新する場合は、最初の側をUSBから外してから同じ手順を繰り返す。
9. 全対象の完了後にUSBを外し、左右の電源を入れる。左右が接続するまで数秒待つ。

リセットボタンの位置が確認できない場合は作業を止め、写真または製作者資料で位置を確認する。基板の `RST` と `GND` を短絡する方法は存在するが、利用者が購入者である本プロジェクトでは、位置を確認せず実施しない。

通常のキーマップ・エンコーダー調整では `settings_reset` を書き込まない。これはBluetoothプロファイルやsplit bondなどの永続設定を消去する復旧手順であり、左右が再接続しない場合などに目的と影響を確認してから使用する。

## macOSでの書き込み

最初に `--dry-run` で対象を検証する。

```bash
scripts/flash-uf2-macos.sh \
  --firmware firmware/zmk-config-MKB2/main/MKB_L_MODULE_ENC.uf2 \
  --expect MKB_L_MODULE_ENC \
  --dry-run
```

表示内容と利用者の確認後、`--dry-run` を外して実行する。対話プロンプトへ `FLASH` と入力した場合だけコピーされる。

```bash
scripts/flash-uf2-macos.sh \
  --firmware firmware/zmk-config-MKB2/main/MKB_L_MODULE_ENC.uf2 \
  --expect MKB_L_MODULE_ENC
```

複数のUF2ドライブがある場合、スクリプトは停止する。対象が確実な場合だけ `--volume /Volumes/<name>` で明示する。

## 完了確認

- コピー後にUF2ドライブが自動的にアンマウントされ、コントローラーが再起動することを確認する。
- 左側はcentralなので、最初に左側をUSB接続してキーまたはポインティング入力を確認してから、Bluetooth接続を確認する。右側はperipheralなので、右側だけをUSB接続しても通常のキーボード入力がホストへ出ないことがある。
- 通常のUF2更新ではBluetoothの保存設定は維持される。HID記述子を変更しておらず、`settings_reset` も使っていない場合は、最初からペアリングを削除しない。
- スクリプトのコピー成功だけでファームウェア動作確認済みとは判断しない。

## 使用しない経路

`scripts/flashgh.ps1` と `scripts/flash.ps1` はWindows前提かつ現在のリポジトリと不整合があるため、修正・検証されるまで使用しない。
