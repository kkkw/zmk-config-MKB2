# 左エンコーダー通常解像度スクロール候補

記録日: 2026-08-29

## 変更目的

左EC11エンコーダーの1ノッチが、通常解像度のスクロールイベントを確実に1つ生成する状態を作る。Bluetooth、split、ZMK revision、HID記述子は変更せず、原因を切り分けられるようエンコーダーbehaviorだけを変更した。

## 候補設定

`config/MKB.keymap` の `scroll_encoder` を次の値にした。

- 上方向: `MOVE_Y(64)`
- 下方向: `MOVE_Y(-64)`
- `tap-ms`: `24`
- `&msc` の生成周期: 既定の16msから変更なし

最初の周期で `floor(64 * 16 / 1000) = 1` イベントを生成し、2回目の周期より前に解放する意図である。

## ビルド検証

`scripts/build-zmk-local.sh --target both` は成功した。既存のdeprecated symbol等の警告は出たが、新規のビルドエラーはない。

| 対象 | サイズ | SHA-256 |
| --- | ---: | --- |
| 候補 `MKB_L_MODULE_ENC.uf2` | 921,600 bytes | `e0bbaef2cba645f9da9b85acc340201885d935c62a7b61197c67b8934312a4e2` |
| 変更なし `MKB_R_MODULE_TBv4.uf2` | 651,264 bytes | `e954106feb8241d666c9b1a68e0973ccdadbc70c9799efdd1df5061d9c43d046` |

生成済みDeviceTreeでは、bindingsが `0x40` / `0xffc0`、`tap-ms` が `0x18` に展開されたことを確認した。右UF2は変更前と同一ハッシュである。

## 復旧用ファームウェア

変更前の左UF2は `build/rollback/c2ce67d/MKB_L_MODULE_ENC.uf2` に保存している。

- SHA-256: `baca5e5aa138d19dba7b0637a4a91e37cbf5072b6e75bf7403a4e3c44d6d3da3`

`build/` はGit管理外である。Docker volumeや作業ディレクトリを削除する前に、復旧用UF2が必要か確認する。

## 実機試験

左側へ候補UF2を書き込んだ。macOS側のコピー処理は最後に `Device not configured` を報告したが、UF2ドライブが消えた後、利用者が実機で候補ファームウェアの反映を確認した。この環境では、UF2書き込み後のドライブ切断に伴う終了時エラーとして扱う。スクロール挙動とBluetooth安定性の試験結果はまだ未記録である。

1. USB接続中に、上下それぞれをゆっくり1ノッチずつ10回動かし、無反応、逆方向、複数イベントがないか確認する。
2. 上下それぞれを連続回転し、入力の詰まり、回転後に続くスクロール、キー入力遅延がないか確認する。
3. USBを外して左右を起動し、既存Bluetooth接続で同じ試験を行う。
4. 通常キーと右トラックボールを操作し、チャタリング、フリーズ、左右切断、起動不能がないか確認する。
5. 結果とOS側のスクロール設定をこの文書へ追記する。

方向が逆の場合は速度の符号だけを入れ替える。無反応または複数イベントがある場合は、観測結果を記録してから速度または `tap-ms` の一方だけを調整する。
